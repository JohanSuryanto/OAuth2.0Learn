# Data Model: Google OAuth Login Dashboard

**Feature**: [spec.md](./spec.md) | **Date**: 2026-09-23

## Persistent (PostgreSQL)

### `users`

| Column | Type | Constraints | Source |
|--------|------|-------------|--------|
| `id` | `uuid` | PK, generated by the app (`Guid.CreateVersion7()`) | — |
| `google_subject` | `text` | NOT NULL, **UNIQUE** | Google `sub` claim (stable account ID) |
| `email` | `text` | NOT NULL | Google `email` claim |
| `display_name` | `text` | NULL | Google `name` claim |
| `created_at` | `timestamptz` | NOT NULL | set on first sign-in (UTC) |
| `last_login_at` | `timestamptz` | NOT NULL | set on every sign-in (UTC) |
| `session_version` | `integer` | NOT NULL, DEFAULT 0 | incremented on logout; sessions carrying an older value are rejected (FR-019) |

**Entity (C#)**: `User { Guid Id; string GoogleSubject; string Email; string? DisplayName; DateTimeOffset CreatedAt; DateTimeOffset LastLoginAt; int SessionVersion; }`

**Validation rules**
- `GoogleSubject` and `Email` are required. If Google returns no email, or the email is not verified (`email_verified`/`verified_email` is not `true`), sign-in fails (FR-018).
- Users are matched on `google_subject` only, never on email. An email change updates the existing row (spec edge case, FR-015).
- The unique index on `google_subject` guarantees one row per Google account (SC-007).

**Lifecycle**

```text
(no row) ──first sign-in──▶ created (created_at = last_login_at = now)
created  ──later sign-in──▶ updated (last_login_at = now; email/display_name refreshed)
logout   ──────────────────▶ session_version += 1 (row kept, FR-016; all sessions revoked, FR-019)
```

No delete path in this feature.

**Not stored**: Google access, refresh, and ID tokens (`SaveTokens = false`), and sessions.

## Transient (not in DB)

### Session (auth cookie)

An encrypted ASP.NET Core auth cookie (Data Protection). Claims:

| Claim | Value |
|-------|-------|
| `ClaimTypes.NameIdentifier` | Google `sub` |
| `ClaimTypes.Email` | email |
| `ClaimTypes.Name` | display name (if present) |
| `app_user_id` | `users.id` |
| `session_version` | `users.session_version` at sign-in |
| `auth_time` | sign-in time, Unix seconds UTC |

- Lifetime: 60 min sliding, **max 8 h from `auth_time`**, browser-session cookie (non-persistent).
- Validated on every request (`OnValidatePrincipal`). The session is rejected if:
  - the user row is missing;
  - `session_version` ≠ `users.session_version`;
  - `now - auth_time > 8 h`;
  - the DB can't be reached (fail closed).
- States: `signedOut` → (Google success + verified email + DB upsert OK) → `signedIn` → (logout / idle 60 min / 8 h cap / revoked) → `signedOut`.

### Frontend auth state

```ts
type AuthState =
  | { status: "loading" }
  | { status: "signedOut"; error?: string }
  | { status: "signedIn"; user: { email: string; name?: string } };
```

This state comes from `GET /api/auth/me` on load and after the popup finishes. See [contracts/auth-api.md](./contracts/auth-api.md).
