  - find the user by `GoogleSubject` (match on `google_subject` ONLY, never email);
  - if not found: insert with `Id = Guid.CreateVersion7()`, `CreatedAt = LastLoginAt = now`, and `SessionVersion = 0`;
  - otherwise: set `Email`, `DisplayName`, and `LastLoginAt = now`, leaving `SessionVersion` unchanged;

- [X] T023 [P] [US1] Create the static page `frontend/public/auth-complete.html` plus `frontend/public/auth-complete.js`. They are served by Vite at `http://localhost:5174/auth-complete.html`, the same origin as the dashboard, and Vite does not transform files in `public/`.
  - **The HTML**: has `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'self'">`, contains NO inline script, and loads `<script src="/auth-complete.js"></script>`. The body text reads "Sign-in finished. You can close this window."
  - **The JS**:
    - reads `result` from the query string and allows only `success`, `access_denied`, `signin_failed` (anything else is treated as `signin_failed`);
    - builds `msg = { type: "oauth-result", success: result === "success", error: result === "success" ? undefined : result }`;
    - sends it through `new BroadcastChannel("oauth-login").postMessage(msg)`, then closes the channel;
    - ALSO calls `window.opener?.postMessage(msg, location.origin)` inside try/catch;
    - then calls `window.close()`.
  
  BroadcastChannel is the primary path because Google's Cross-Origin-Opener-Policy can null out `window.opener` (research R2). FR-021
- [X] T024 [US1] Create `backend/OAuthLearn.Api/Auth/GoogleAuthEvents.cs` with three handlers, wired into `.AddGoogle(o => { o.Events.OnCreatingTicket = ...; o.Events.OnAccessDenied = ...; o.Events.OnRemoteFailure = ...; })` in `Program.cs`. Depends on T022.
  - **`public static bool IsEmailVerified(JsonElement userInfo)`**: returns true ONLY if property `email_verified` or `verified_email` exists and is JSON `true` (or the string `"true"`). A missing property or any other value returns false, so the check fails closed (FR-018, research R5c S2).
  - **`OnCreatingTicket`**:
    1. Read `ClaimTypes.NameIdentifier` (sub), `ClaimTypes.Email`, and `ClaimTypes.Name` from `context.Principal`.
    2. If sub or email is missing, throw `InvalidOperationException("Google account has no email")`.
    3. If `!IsEmailVerified(context.User)`, throw `InvalidOperationException("Google email not verified")`.
    4. Resolve `UserService` from `context.HttpContext.RequestServices` and call `UpsertFromGoogleAsync`.
    5. Add these claims to `context.Identity`:
       - `new Claim("app_user_id", user.Id.ToString())`
       - `new Claim("session_version", user.SessionVersion.ToString())`
       - `new Claim("auth_time", timeProvider.GetUtcNow().ToUnixTimeSeconds().ToString())`
  - **`OnAccessDenied`** (Google returned `error=access_denied`, i.e. the user cancelled or declined): `context.Response.Redirect("/api/auth/popup-complete?error=access_denied")`; `context.HandleResponse()`.
  - **`OnRemoteFailure`** (everything else: DB error, missing or unverified email, bad state): log `context.Failure`; `context.Response.Redirect("/api/auth/popup-complete?error=signin_failed")`; `context.HandleResponse()` (FR-012, FR-017).
  
  Do NOT detect access_denied by string-matching `Failure.Message`

## Phase 5: User Story 3 - Stay signed in across page reloads (Priority: P2)
